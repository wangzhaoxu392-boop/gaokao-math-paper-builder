# 本地与云端模型分工

## 本地模型

- `bge-m3:latest`：本地语义检索和相似题候选，不直接把 OCR 文本作为事实。
- `nomic-embed-text:latest`：嵌入模型不可用时的备用。
- `qwen2.5:7b`：文本清洗、题型初标、知识点初标和低风险 L1/L2 题初筛。
- `deepseek-r1:14b`：可选本地疑难初筛，不替代正式复核。
- 缺答案的 L1–L3 纯文本题可先由本地模型生成初解；本地结果仍须与云端独立结果一致才能自动放行。

Ollama 地址固定为 `http://127.0.0.1:11434`。本地返回必须符合 JSON 结构；格式错误最多重试一次。

## 云端模型

复杂定级、跨年级范围判断、AI 改编、原创题生成、解答题复算和最终质量门禁使用当前 Codex 配置。不得在 skill 内硬编码具体云端模型名。

## 自动升级

遇到以下任一情况时立即转为线上复核：

- 图形、扫描公式、手写批注或答案缺失。
- 跨学期、旧教材、多个答案版本或题号冲突。
- L4、L5、证明、构造、创新题。
- 本地输出低置信度、非法 JSON、超时或与规则冲突。

本地模型不可用、算力不足或超时不得等待多轮，也不得直接判定题目无效；应马上冻结本地阶段并升级线上。线上按两次彼此独立的复核执行，第二遍不得看到第一遍答案或本地答案。两次一致才能自动改正、补答案或定档；两次冲突、均明确表示无法判断，或线上连续失败时才进入人工队列。只有两次线上复核都判定题目结构不可修复时才允许自动排除。

定时巡检与答案修复共用同一升级顺序：确定性规则 → 本地 Ollama → 两次独立线上 → 人工。不得把“可能需要人工”的普通题批量直接排除。

批量答案修复按题目哈希、模型 digest、提示词版本和 Schema 版本缓存，并记录耗时、token 和重试次数。

常规组卷默认 `generation.fast_path=true`，不调用云端代理；题量不足时使用相邻档补足。若是库里完全没有的题型/档位组合，默认跳过耗时的本地生成并立即切换当前线上模型出题，再由第二次独立线上求解核对；只有一致时才入库。

窗口的常规组卷优先使用确定性选题和文档渲染，不调用云端代理。模型只用于缺口补题、复杂答案修复和内容复核；线上失败题自动丢弃，不进入用户待办。

## 预算

- 教学卷云端软预算 40,000 tokens。
- 完整考试卷和批量入库 80,000 tokens。
- 达到 80% 提示，达到 100% 暂停并询问。

模型结果只按“模型、digest、提示词版本、Schema 版本、输入哈希”复用。定时巡检按批次检查时间轮转，已本地通过或线上验证的题在复检间隔内不重复调用模型；人工题默认 30 天后才重新尝试。
